# v1.1.0 — Batch editing and server datasets

Fancy UI Grid now supports validated bulk editing and lazy server datasets in both React and Streamlit.

## Validated batch editing

- Stage inline edits, clipboard paste, and fill operations before committing.
- Review original and pending values; Save all, Discard all, or discard individual changes.
- Use text, number, date, boolean, select, or custom React editors with column and cross-field row validation.
- Undo and redo draft operations. Failed saves preserve drafts and display server errors.
- Submit one asynchronous batch callback with original values for conflict checks. The SQLite adapter validates and saves a batch atomically.
- The repricing demo now saves premium edits as a batch and updates differences and formulas.

## Lazy server row model

- Load viewport blocks and group children on demand with a bounded cache, request deduplication, concurrency limits, cancellation, and retry.
- Send filters, multi-column sorting, grouping, pivot dimensions, and value metrics to the backend.
- Display server-calculated group aggregates, pivot results, and full-query totals.
- Use compressed scrolling for very large row counts without allocating every row in the browser.
- Connect through the JSON HTTP datasource or Streamlit Python callbacks. The included SQLite adapter and examples exercise one million records.

## Compatibility and scope

Existing immediate cell editing and the controlled `serverSide` paging API remain available. Opt into the new features with `editMode="batch"` and `dataSource` (Python: `edit_mode`, `on_batch_save`, and `data_source`).

Remote rows use a fixed height. Copy, find, charts, and export operate on the loaded viewport; full-dataset export belongs in the backend. Selecting all unloaded rows is not implemented. The backend owns remote calculated fields and totals. Refresh/query changes collapse groups and reset scrolling while retaining pending edits.

## Validation

Verified locally with 81 JavaScript unit tests, 10 Python adapter/transport tests, the Streamlit AppTest smoke test, and eight browser scenarios. Browser coverage includes a 500-cell paste/undo/save, validation and failure recovery, repricing formulas, scrolling to row 1,000,000 with a bounded DOM, filtering/grouping/pivot totals, and Streamlit persistence across reruns.

Type checks, Next.js production and GitHub Pages export builds, and the Streamlit frontend production build pass. CI includes the unit tests, browser preview/repricing tests, and Python checks; live database and Streamlit browser tests are opt-in as documented in the guide.
